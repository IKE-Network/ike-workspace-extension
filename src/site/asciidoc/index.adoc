= IKE Workspace Extension

image:https://img.shields.io/maven-central/v/network.ike.tooling/ike-workspace-extension[Maven Central,link=https://central.sonatype.com/artifact/network.ike.tooling/ike-workspace-extension]

`network.ike.tooling:ike-workspace-extension` is a Maven 4 build
extension that prunes non-existent `<subprojects>` entries from IKE
workspace POMs before model validation. Lets a fresh clone of any
IKE workspace bootstrap with `mvn ws:scaffold-init` even when no
subproject directory is on disk yet.

== What it does

When Maven 4 reads a workspace POM declaring several subprojects but
the working tree only has the workspace root (because the operator
just ran `git clone` and has not yet populated subprojects), Maven's
model validator fatally aborts the build with *"Child subproject X
does not exist"* — before any goal can run. That makes the
documented bootstrap (`git clone && cd && mvn ws:scaffold-init`)
impossible. See
link:https://github.com/IKE-Network/ike-issues/issues/459[IKE-Network/ike-issues#459].

This extension implements
`org.apache.maven.api.spi.ModelTransformer.transformFileModel`,
which fires *before* profile activation and subproject existence
validation. For any POM whose directory has a sibling
`workspace.yaml` (the "this is a workspace POM" marker), the
transformer:

. Removes `<subprojects>` entries whose `<sub>/pom.xml` does not
  exist on disk.
. Removes file-activated profiles whose `<file><exists>` target
  is missing — so any `-P?with-X` flag on the command line
  silently no-ops on the missing profile name.

Every other POM passes through untouched.

== Build lock and missing-module diagnosis

Every working-set build takes an exclusive OS file lock on
`<root>/.mvn/target/build.lock` when project discovery starts and
holds it until the session ends. A second build of the same tree
waits, saying every 30 seconds who holds the lock (pid, host, start
time, goals and `-pl`), and fails after `-Dike.build.lock.timeout`
(default `30m`; `PT45M`, `90s`, `2h` also work) with the holder
named. A member built from its own root locks its working set's
tree. `-Dike.build.lock=false` skips the lock, and so do sessions
whose goals are all read-only (`validate`, `help:*`,
`dependency:tree`/`list`/`resolve`, `ws:*-draft`).

Only the outer Maven session locks: a Maven started by the holder
(`exec`, the invoker, a `ws:` goal running `mvn`) finds its ancestor
in the lock file and proceeds unlocked. The OS releases the lock
when the holder exits, Ctrl-C and crashes included, so a dead build
never wedges the tree. IntelliJ's Maven sync neither takes nor waits
for the lock; IDE builds take it only when delegated to Maven.

When a compile fails with javac `module not found: X`, or a test
fork with `NoClassDefFoundError`/`ClassNotFoundException` for a
reactor sibling's class, the extension logs a diagnosis (and saves it
under `.mvn/target/ike-diagnostics/`): the sibling's `target/classes`,
whether the class or `module-info.class` is there and when it was
written relative to the build's start and to this session's own
compile of the sibling, the file the dependency resolved to (reactor
class directory, packaged jar, project-local repository, or local
repository), and other processes working in the tree. It tells an
outside writer apart from Maven resolving or ordering the sibling
wrongly (MNG-8096).

== Stability commitment

This artifact does exactly one thing and never grows. The
dependency surface stays at the Maven 4 API jars (compile scope,
loaded into the extension classloader), plus `maven-core` (provided)
for the session-level build lock and diagnosis. No `ike-*` runtime
dependencies, no business logic, no knowledge of IKE conventions
beyond _"sibling `workspace.yaml` marks a workspace POM."_

Versioned independently of the
link:https://github.com/IKE-Network/ike-platform[ike-platform]
release cadence. If we ever need different behavior, we add a
separate extension rather than evolving this one.

== Wiring

Declared in a workspace's `.mvn/extensions.xml`:

[source,xml]
----
<extensions>
    <extension>
        <groupId>network.ike.tooling</groupId>
        <artifactId>ike-workspace-extension</artifactId>
        <version>1</version>
    </extension>
</extensions>
----

The ike-platform workspace plugin's `ws:scaffold-init` writes this
entry into new workspaces automatically; `ws:scaffold-publish`
keeps it in sync on existing workspaces. The version is sourced
from a property declared in `ike-parent` — operators do not
maintain it by hand.
